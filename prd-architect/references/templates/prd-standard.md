# PRD-standard Template

用于常规产品功能、列表 / 表单 / 面板、跨状态交互。目标是让产品、设计、研发、测试对齐主流程和边界。

Standard 不是开发 handoff。默认写产品对象、业务规则、页面状态、交互逻辑和验收标准；字段、接口、schema 只有在用户明确要求开发 handoff 时才进入附录。

## Output Skeleton

### 0. 文档信息

| 字段 | 内容 |
| --- | --- |
| 功能名 |  |
| 需求类型 | PRD-standard |
| 当前状态 | 草稿 / 讨论中 / 已确认 |
| 关联模块 |  |
| 更新时间 |  |

开头必须用一句话说明：本期只解决什么。

### 1. 功能目标

写：

- 背景：为什么现在需要做。
- 目标：用户或业务要达成什么。
- 成功标准：怎么判断做对了。
- 非目标：本期不做什么。

### 2. 用户场景

保留 2-3 个关键场景。每个场景写清用户、触发条件、期望反馈和结果。

### 3. 全局结构图 / 核心流程图

启用条件：

- 存在多阶段链路。
- 存在上下游依赖。
- 涉及对象流转或状态切换。
- 用户要求可编辑流程图 / 架构图。

如果只是一个现有页面区域内的局部改动，可以降级为 ASCII 结构、真实页面截图或 HTML mockup。

正式图示时读取 `references/drawio-templates.md`。

### 4. 入口与触发

写清：

- 用户从哪里进入。
- 系统在什么状态下展示。
- 哪些条件下不展示或不可用。
- 触发后的第一反馈是什么。

### 5. 页面结构与信息布局

写用户可见的信息结构，不写组件实现细节。

涉及既有页面时，读取 `references/mockup-handoff.md`，优先基于真实页面截图或静态 HTML mockup 说明新增区域。

### 6. 核心对象与业务规则

这一节替代旧的“数据与字段”。默认写产品层对象和用户可见规则：

- 涉及哪些业务对象。
- 用户如何感知这些对象。
- 哪些规则影响展示、点击、确认、失败、恢复。
- 哪些对象需要在下一轮对话或后续流程中被引用。

不要在主文档写 TypeScript interface、JSON schema、endpoint、adapter 或 metadata。需要这些内容时，读取 `references/handoff-appendix.md`，放入开发 handoff 附录。

### 7. 交互逻辑

写：

- 正常流程。
- 状态切换。
- 用户确认点。
- 系统反馈。
- 恢复或撤销策略。

### 8. 异常与边界

用表格写：

| 场景 | 处理 | 用户可见反馈 | 验收方式 |
| --- | --- | --- | --- |

### 9. 验收标准

写可测试 checklist，覆盖正常流、异常流、边界条件和恢复行为。

### 10. 待确认事项

只列阻断决策或真实未决问题。若有 3 个及以上待确认项，当前状态通常不应写成 `已确认`。

### 11. 关联产物

只链接本轮真实存在或明确要产出的文档、截图、HTML mockup、Draw.io 图示、PRD review 结果。不要为了显得完整列大量代码文件。

## Compression Rules

- 不要同时用背景、目标、核心规则、页面行为、实现要求重复同一条规则。
- 页面变化能通过截图表达时，不用大量文字描述布局。
- 只影响一个现有页面区域时，不强制一体化总图。
- 每个章节都要回答新问题；重复内容合并。

## Handoff Boundary

只有用户明确说“开发 handoff / 字段定义 / 接口协议 / schema / metadata / adapter / 实现计划前置材料”时，才加载 `references/handoff-appendix.md`。

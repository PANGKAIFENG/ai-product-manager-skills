# PRD Shape Gates

按需加载本文件。用于生成后自检 PRD 是否结构过重、章节误激活或过早技术化。

## Product Draft Gates

适用于 `草稿` 和 `讨论中` 阶段：

- 是否用一句话写清本期只解决什么。
- 背景是否在不超过 200 字内说明当前问题、主要影响和为什么现在处理，且没有为凑字数扩写。
- 是否只加载一个 PRD 模板。
- 是否没有把字段、schema、metadata 写进产品主链路。
- 是否保留真实待确认项。
- 是否没有把草稿误推成开发计划。
- 是否以功能模块承载用户、触发、行为、UI 反馈和可验证结果，没有机械展开重复章节。

## Version History Gates

适用于所有新建或修订 PRD：

- PRD 标题后的第一个 H2 是 `版本记录`，表头为 `版本 / 日期 / 修改内容`。
- 新建 PRD 从 `V1.0` 开始，并记录当天日期和 `首次创建`。
- 修订已有 PRD 时保留全部历史，最新版本置顶且版本号不重复。
- 普通功能、交互、文案或规则迭代默认增加小版本；产品目标、范围、核心信息架构或核心流程发生实质变化时增加主版本。
- 修改内容写明本轮真实变化，不使用“更新 PRD”“优化文档”等空泛描述。
- 发布重试、回读、同内容截图重拍、纯格式整理或不改变产品含义的错别字修正不增加版本。

## Publish-ready Gates

适用于用户明确要上传钉钉、发布到在线文档或发给开发直接阅读的 PRD：

- 文档信息表不包含 `关联 mock`、本地 HTML、PNG、`file://`、`localhost` 或 `dingtalk-assets`。
- 顶部版本记录已更新到本轮产品内容，且可以由 Publisher 回读比对最新版本行。
- mock 截图放在对应功能模块、页面状态或交互章节下。
- 默认不输出“关联产物”聚合章节。
- 默认不输出“待确认事项”正文；未决问题转到最终说明或本地草稿附录。
- 不保留失败图、重复图或只有本机可访问的链接作为正文入口。

## Mockup Evidence Gates

只要 PRD 定义用户可见的页面、弹窗、抽屉、表单、卡片或可见状态变化，就默认触发 UI 证据链；不需要用户再次明确要求 HTML 或截图：

- 已生成独立的 HTML mockup artifact；文件真实存在、非空、可直接打开，并与本期 PRD 状态一致。
- 关键页面/模块已经实际渲染并截取，不只写“截图承接”说明。
- 截图位于它解释的功能、页面或状态章节，而不是只在“关联产物/本地草稿附录”。
- 本地 Markdown 图片引用指向真实存在的文件。
- 当前状态截图和目标状态截图有明确标签，不混用。
- 旧原型与新 PRD 的页面结构不一致时，已先更新原型或明确转交 UI mockup，未把旧截图当目标设计。

只有以下情况可以正式跳过，并必须说明原因、受影响页面或状态以及待补动作：

- 需求完全没有用户可见界面，例如纯后端 API、数据策略或基础设施规则。
- 用户明确要求只交付纯文本，且已知不会进入页面实现或视觉评审。
- 页面范围、入口或关键交互存在阻断性决策，继续固化会制造误导。
- 目标项目或 UI 证据不可访问，无法形成有证据的静态复刻；不得伪造组件、token 或生产对齐结论。
- 浏览器或截图工具当前不可用，且已保留可打开 HTML、记录验证缺口和补证动作。

## Template-specific Gates

### PRD-lite

- 只保留短背景、功能模块和必要待确认；可验证结果写进功能逻辑和 UI 反馈。
- 页面变更以目标态截图和一张功能逻辑表为主体。
- 默认不生成流程图；复杂到需要图或用户明确要求图示时升级为 Standard。明确要求时直接启用 Draw.io。

### PRD-standard

- 不要求固定标题；至少清楚表达背景与范围、功能模块、功能逻辑、边界和可观察结果。
- 用户、触发、页面状态、系统行为和 UI 反馈位于对应功能模块，不在平行章节重复。
- 相近状态存在主体或作用域歧义时，明确主体、判定时点、影响范围和用途。
- 只有跨多角色/系统、关键判断或回流、异步恢复、6 个及以上依赖步骤，或用户明确要求时才启用 Draw.io。

### PRD-ai-native

- 人工动作、AI 动作、系统反馈和接管边界位于对应功能模块。
- 状态反馈和人工确认闭环清楚。
- 只有真实存在跨轮上下文时才启用记忆章节；技术 schema 放 handoff 附录。

## Over-technical Warnings

产品初版正文出现以下内容时通常需要降级或移到 handoff 附录：

- `interface Xxx`。
- ```ts / ```typescript 代码块。
- ```json 代码块。
- `metadata`、`adapter`、`endpoint`、`schema` 作为章节核心。
- `requiredCapabilities`、`capability registry`、`action_template_registry` 等实现治理细节。
- 大量真实代码路径列表。

## Readiness Gates

PRD 只有满足以下条件，才建议进入 `writing-plans`：

- 目标用户、问题、范围边界和非目标明确。
- 主流程、关键状态、输入输出、异常或人工接管点清楚。
- 关键动作的系统行为、用户反馈、失败结果和恢复方式可测试、可人工检查或可通过具体 artifact 验证。
- 阻断性待确认项已经关闭，或显式转成 implementation plan 前置假设。

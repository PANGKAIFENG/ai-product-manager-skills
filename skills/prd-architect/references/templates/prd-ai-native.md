# PRD-ai-native Template

用于 AI 判断、生成、推荐、记忆、人工确认或人工接管是需求核心的产品。目标是写清人、AI 和系统如何完成任务，同时保持正文围绕功能模块而不是能力清单展开。

不要因为需求中出现 Agent、Workflow 或 AI 就自动使用本模板。普通 UI 限制、提示、权限或配额仍使用 Lite / Standard。

## Output Skeleton

省略任何“按需”章节时，后续章节顺次重编号，不保留编号空档。

### 版本记录

放在 PRD 标题之后、文档信息之前。新建 PRD 使用 `V1.0`；修订已有 PRD 时保留旧记录并把最新版本置顶。

| 版本 | 日期 | 修改内容 |
| --- | --- | --- |
| V1.0 | YYYY-MM-DD | 首次创建 |

### 1. 背景与目标

- **背景**：最多用 200 字说明当前任务为什么需要 AI 参与以及现有问题；能更短说清就不要凑字数，不写行业综述。
- **本期只解决**：一句话写清范围。
- **成功标准**：用户结果、AI 结果和可观察质量各 1 条以内。
- **不做**：只列容易造成范围误解的内容。

### 2. AI 协作边界

用一张短表说明职责，不展开成长篇能力列表：

| 人工负责 | AI 负责 | 系统反馈 | 必须停止 / 转人工的条件 |
| --- | --- | --- | --- |
|  |  |  |  |

### 3. 核心流程（按需）

用户明确要求正式图示时直接生成 Draw.io。用户未明确要求时，只有跨多个角色/系统、存在关键判断或回流、包含异步等待/恢复，或主链路达到 6 个及以上依赖步骤才生成；轻量对话建议、单页生成操作或局部 AI 状态不画流程图。

启用时读取 `references/drawio-templates.md`，生成可编辑 `.drawio` 和可预览图。

### 4. 功能模块

每个用户可感知的任务阶段或页面区域使用一个模块。

#### 4.x 模块名称

**模块目的**：一句话说明用户在这里完成什么。

**目标态 UI**

页面型模块必须展示目标态截图，并把生成中、待确认、失败、部分成功等关键状态放在对应模块；现状图不能代替目标态。

将生成后的真实截图插入此处，例如：`![目标态：状态名称](path/to/screenshot.png)`。

**功能逻辑**

每一行都要写清可观察的系统反馈、失败结果或人工接管方式。

### 5. 上下文与记忆（按需）

只有本期确实读取或写入跨轮上下文时才启用：

- 哪些信息进入下一轮。
- 哪些内容必须经用户确认才能沉淀。
- 哪些内容不进入长期上下文。

不在产品正文写 metadata schema；需要字段时转开发 handoff 附录。

### 6. 跨模块规则与异常（按需）

只写同时影响两个及以上模块的权限、质量门槛、降级、部分成功、人工接管或恢复规则。

### 7. 待确认事项（仅草稿 / 讨论中）

只列阻断决策或真实未决问题。发布版正文默认省略本节。

## Compression Rules

- 不单列用户场景、页面结构、交互逻辑、模块输入输出或人工接管等平行章节。
- 把用户触发、AI 行为、系统反馈和失败处理写进对应功能模块。
- 没有上下文沉淀时删除“上下文与记忆”；没有跨模块规则时删除对应章节。
- 页面变化优先用目标态截图表达，再用功能逻辑表解释。
- 不输出独立的“模块验收”“整体验收”或“验收标准”章节；可验证结果写进功能逻辑、系统反馈和失败 / 接管列。

## Prohibited In Main Body

- TypeScript interface、JSON schema、endpoint、adapter、hidden metadata 或 capability registry。
- 为了显得完整而生成的 AI 能力清单、装饰性流程图和重复状态描述。

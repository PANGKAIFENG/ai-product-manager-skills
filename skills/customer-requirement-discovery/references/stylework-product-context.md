# StyleWork 产品上下文

仅在需求明确落入 StyleWork 时加载。证据版本和限制见 `stylework-source-manifest.md`。

## 产品定位与结构

StyleWork 当前应按“workspace + session + conversation + Agent task + structured result/artifact”的工作台理解，而不是先假设为传统多菜单业务后台。

核心交互链路：

```text
选择 workspace/session
-> 在 conversation 中提出任务并附加资源
-> Agent/Skill 执行并展示业务进度
-> 以 resource-picker、media part 或 artifact 返回结构化结果
-> 用户选择、查看、继续追问或进入下一业务动作
```

因此，新增能力优先判断能否进入现有会话任务、资源卡片和结果面板；只有需要长期监控、跨任务比较、配置管理或稳定运营看板时，才考虑独立页面。

## 已有可复用能力域

| 能力域 | 可作为何种基础 | 注意 |
| --- | --- | --- |
| Agent 任务底座 | workspace、session、message、Skill/Plugin 装配、任务执行 | 底座存在不等于客户业务已实现 |
| 款式检索 | 自然语言条件到结构化检索结果与 resource-picker | 数据范围、字段和授权仍需按客户场景确认 |
| 面料检索 | 面料筛选、结果卡片与多选交互 | 不等于已接客户私有面料库 |
| 图片生成与服装视觉处理 | 款式图生成、变体、试穿、平铺/3D 转换等工作流基础 | 生产效果需真实样本验证 |
| 视频/媒体生成 | 图片到视频及媒体工作流基础 | 供应商、成本、时长和质量另行确认 |
| 结构化结果 | resource-picker、media result、artifact 类输出 | 新业务需定义结果 schema 和后续动作 |

## 适配分类

| 分类 | 判定 | 对外表达 |
| --- | --- | --- |
| 现有能力 | 已有业务能力可直接演示且证据明确 | 说明版本与限制 |
| 直接复用 | 复用底座或通用组件，无客户特有建设 | 不包装成新增功能 |
| 配置 | 规则、字段、模板、Skill 或工作流配置 | 明确配置对象和验收 |
| 扩展 | 在现有链路增加数据、节点、结果或交互 | 说明复用点与增量 |
| 新建 | 需要新的业务服务、页面或数据模型 | 不因底座存在而降级为配置 |
| 技术验证 | 数据、接口、模型效果或平台政策不确定 | 先定义验证样本与通过标准 |

## 不可默认承诺

- 任意网站、社媒或电商平台的长期稳定抓取；
- 客户私有系统、商品库、面料库已完成连接；
- 未验证平台的账号授权、历史数据、传播指标和自动发布；
- 无真实样本情况下的识别、推荐、预测或生成准确率；
- 全自动无人审核的选款、采购、发布或客户触达；
- 本地临时前端分支中的预览功能已经进入正式产品。

## 澄清问题如何更针对

StyleWork 需求优先确认：

- 用户希望在 conversation 中完成一次任务，还是需要持续运营页面；
- 输入是上传资源、现有资源库、企业数据还是外部平台数据；
- 输出适合 resource-picker、artifact、报告还是新页面；
- 结果之后是选择、编辑、生成、导出、审批还是进入外部系统；
- 现有能力可直接复用，还是要新增客户字段、规则、数据源和审核节点。

仍然遵守动态提问：这些不是每次都要全部问。

# Red Baseline

记录日期：2026-07-24。三组测试均在不加载本 Skill 的条件下执行，用于固定真实失败模式。

## Baseline A：通用模糊需求

输入是一个宽泛的 AI 客户需求。基线直接输出 22 个客户问题，虽能覆盖角色、输入输出、数据、安全和验收，也能区分假设，但没有先与销售或客户成功进行内部访谈。

失败判定：

- 首次响应把问题负担直接转移给客户；
- 没有按信息增益选择每轮问题；
- 没有“事实、假设、未知项、冲突、风险”的持续状态；
- 没有必答与选答优先级，也没有数量上限。

## Baseline B：StyleWork 相关需求

输入是“在 StyleWork 中增加社媒趋势、竞品观察和选款建议”。基线立即生成 8 个必答、5 个选答的客户清单，并给出通用可行性判断。

失败判定：

- 没有先向内部用户追问已有客户背景和售前目标；
- StyleWork 判断停留在“需要核对菜单、工作流和组件”，未使用版本化产品结构与 UI 参考；
- 没有明确区分正式产品证据与本地临时前端证据；
- 一开始就进入最终客户清单，无法利用销售掌握的信息压缩问题。

## Baseline C：过早 Demo

输入只有“根据设计图推荐面料，下周需要 Demo”。基线主动补出用户角色、输入字段、推荐数量、三页流程和示例结果，再附 12 个内部问题。

失败判定：

- 在内部访谈前替客户补了过多产品定义；
- Demo 假设虽有提示，但没有形成可审阅的 Demo Brief 和假设台账；
- 没有明确“允许立即做 Demo”的触发条件；
- 没有控制单轮内部问题数量。

## Forward Test Gates

- 首轮只能提出 1-3 个会显著改变目标、流程、可行性或输出的问题。
- 最多五轮内部访谈；信息足够时必须提前停止。
- 最终客户清单默认必答不超过 8 个、选答不超过 5 个。
- StyleWork 上下文只能条件加载，并区分通用技术可行性和产品适配。
- 信息不足时不主动制作 Demo；明确要求立即制作时必须展示假设与模拟数据边界。

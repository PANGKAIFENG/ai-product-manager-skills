# Green Forward Test

记录日期：2026-07-24。以下五组测试在显式加载本 Skill 的条件下执行，用于验证首次响应、阶段切换和 StyleWork 条件上下文。测试输入保持客户原始的模糊表达，不在提示中泄露期望答案。

## 1. 通用模糊需求

输入：客户希望做一个 Agent，自动汇总海内外趋势、明星和 KOL 穿搭，并基于爆款生成设计方案。

观察：首次回复先复述当前理解，只向销售提出 3 个高价值问题，分别确认业务决策、输入与输出闭环、验收方式；没有直接生成长篇客户问卷，也没有机械追问所有平台、数量和频率。

结果：通过。

## 2. StyleWork 模糊需求

输入：客户希望在 StyleWork 中增加社媒趋势、竞品观察和选款建议，但只提供这一句话。

观察：首次回复仍处于内部需求发现阶段，只提出 3 个问题；按条件加载版本化 StyleWork 产品、UI 和来源清单，没有把临时 UI 证据写成正式能力，也没有提前承诺产品适配。

结果：通过。

## 3. 过早 Demo 请求

输入：客户只说希望根据设计图推荐面料，并要求下周看 Demo。

观察：回复没有直接补造页面和产品定义，只追问 Demo 要验证的决策、可用输入和预期输出 3 个问题；明确需求成熟度不足，若要求立即制作则必须先接受显式假设并完成 Demo Brief。

结果：通过。

## 4. 一次性客户澄清清单

输入：内部用户表示销售侧信息已经回答完毕，要求生成可一次发给客户的清单。

观察：输出包含 8 个必答问题和 4 个选答问题；问题使用客户语言，提供建议回答方式，合并了重复项，并将未确认内容放入暂定假设，不夹带内部可行性结论或交期承诺。

结果：通过。

## 5. 客户回复回收

输入：客户已补充目标用户、业务流程、数据来源、输出、人工审核和验收方法，且明确方案将落入 StyleWork。

观察：输出分别给出客户确认版需求摘要、通用技术可行性和 StyleWork 适配判断；成熟度判为 M3，通用结论为“有条件可行”，并列出数据授权、真实样本和接口验证条件，没有用 StyleWork 现状替代通用可行性判断。

结果：通过。

## 结论

- 五组前向测试均满足阶段路由和问题数量约束。
- 历史失败“首次抛出 22 个客户问题”“StyleWork 上下文无版本依据”“信息不足时过早制作 Demo”均未复现。
- 语义质量仍依赖人工评审；契约测试只用于验证文件、数量和关键边界是否持续存在。

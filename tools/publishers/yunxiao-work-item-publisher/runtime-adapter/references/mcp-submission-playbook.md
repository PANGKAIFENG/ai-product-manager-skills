# 云效 MCP 提交与回读流程

## 1. 实时发现工具契约

不同客户端可能给云效 MCP 工具使用不同名称和参数。每次运行都查看当前工具 schema，并识别以下等价能力：

- 创建工作项：等价于 `CreateWorkitem`；
- 获取单个工作项：等价于 `GetWorkitem`；
- 搜索/列出工作项：用于重复检查和模糊创建结果恢复；
- 创建附件与列出附件：用户明确要求上传时用于创建后的附件写入与回读；
- 列出项目、类型、迭代、成员和模块：用于把显示名解析为稳定 ID。

缺少创建或回读能力时停止。不要凭记忆构造工具名、参数、类型 ID 或字段 ID。

## 2. 身份解析

1. 从当前页面 URL、用户消息或 MCP 项目列表取得候选项目 ID。
2. 同时读取项目显示名并放入预览，让用户确认目的地。
3. 将 `需求`/`缺陷` 映射到该项目实时返回的工作项类型 ID。
4. 迭代、负责人和子模块存在重名时，展示候选并请求用户选择；不得选择第一个结果。
5. 无法解析的可选字段保持未指定；无法解析项目或类型则阻塞。

## 3. 重复检查

规范化标题时只做首尾空白和连续空白归一化，不改写语义。优先在同一项目、同一类型内搜索完全相同标题，再检查高度相似标题。

找到候选时输出：`ID、标题、类型、状态、迭代、URL`。默认停止；用户解释差异后重新拟定标题并重新确认。

搜索能力不可用时，在预览中明确写：

```text
重复检查：未完成（当前云效 MCP 未提供可用的搜索/列表能力）
风险：可能创建同名或重复工作项
```

## 4. 确认载荷

本地校验脚本对除 `confirmation` 外的载荷生成 fingerprint。预览展示的字段、描述和证据都属于确认范围。

用户确认后写入。附件清单属于 canonical payload，至少包含最终文件名、MIME、字节数、SHA256 和敏感性检查结果：

```json
{
  "confirmation": {
    "status": "confirmed",
    "confirmed_by": "user",
    "confirmed_at": "ISO-8601 timestamp",
    "confirmed_fingerprint": "sha256 fingerprint from preview"
  }
}
```

任何字段变化都会生成新 fingerprint，旧确认不得复用。

## 5. 创建一次与模糊失败恢复

调用创建工具前记录本地 fingerprint 和调用时间。创建工具只调用一次。

若返回超时、连接中断或未知错误：

1. 不立即重试；
2. 按项目、类型、精确标题和调用时间窗口搜索；
3. 找到唯一候选时按 ID 回读并继续验证；
4. 找到多个候选时报告冲突，不更新或删除；
5. 无法搜索或没有确定结果时标记“提交结果未知”，停止。

只有确认远端没有创建对应工作项，并获得用户新的明确确认后，才能再次调用创建工具。

## 6. 附件上传

1. 先检查附件不包含敏感信息，文件名含扩展名，MIME 与文件一致，单文件不超过实时 MCP schema 的限制。
2. 只在工作项已返回稳定 ID 后上传。远程 HTTP MCP 使用 base64 内容和最终文件名；`filePath` 只用于 MCP Server 与调用方同机的 stdio 场景。
3. 逐项记录成功与失败结果。附件失败不能触发第二次创建工作项，也不能自动删除已创建的工作项。
4. 描述只引用最终文件名，不写 `/tmp`、`/var/folders` 或包含用户名的本地绝对路径。

## 7. 回读验证

创建返回 ID 后立即按 ID 回读。比较用户确认过的每个字段：

| 状态 | 定义 | 输出 |
| --- | --- | --- |
| `已创建且验证通过` | ID 可读回，所有已提交字段一致 | 报告 ID、URL 和验证字段 |
| `工作项已创建，附件上传失败` | 工作项有稳定 ID，但至少一个确认附件未上传或回读缺失 | 报告 ID、URL、成功/失败文件名，不重复建单 |
| `已创建但验证失败` | 已有稳定 ID，但字段不一致或无法完整读回 | 报告差异，不自动修复 |
| `提交结果未知` | 无法判断远端是否创建 | 保留草稿和时间，禁止盲目重试 |
| `未创建` | 在调用前阻塞或创建明确失败且确认无远端记录 | 报告阻塞点和恢复动作 |

不要把“创建工具返回成功”或“附件工具返回成功”单独当成完成；工作项和附件列表都要回读。
